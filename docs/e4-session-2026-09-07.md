# E4 — the autonomous session of 2026-09-07

The record of one session in which an agent worked Epic [#212](https://github.com/Strycher/Field_Compass/issues/212) (break up the `src/src.ino` god object) alone, under a standing grant from the owner, for about six hours. It exists so that anyone — the owner in a month, another agent tomorrow — can see what was decided, why, under what authority, and what was deliberately left undone. The per-band engineering records are §8–§15 of [`god-object-inventory.md`](god-object-inventory.md); the raw proof outputs are in [`e4-proofs/`](e4-proofs/). This document is the decision log that ties them together.

The agent's confirmed reading, which the owner accepted before leaving:

- Merge its own PRs after CI is green and the `nm` proof passes, with an approval comment that says plainly "merged autonomously under the owner's standing grant of 2026-09-07" — never "human approval received".
- Make and list reasonable calls: unit grouping, header placement, closing task issues whose PR merged.
- Set aside anything behaviour-changing, any flash, closing Epic #212, #99 itself, and anything destructive (archive, force-push, directory deletion).

Every standing constraint stayed in force: SAFELANE gates and checkpoints, `dw` task claims before commits, the two-task convention (work task closed before push, PR task carries the merge), no raw flash, no parentless issues, no closing of issues that need the owner's agreement.

## 3. Decisions made under the grant, and why

Each of these is also in the PR body it belongs to, marked "for review". Any of them can be reversed; none changes behaviour.

### 3.1 Band 3 was split into five children by dependency layer, with the web unit last

[#264](https://github.com/Strycher/Field_Compass/issues/264) said "taken in removal order, `webServer` first" and "expect this to be split into one child task per domain once band 2 has landed". The split happened, but not per domain and not web-first. The relocation graph after band 2 showed `webServer` referenced only by the 23 web handlers, `initWebServer` and `loop`, with `initWiFi` calling `initWebServer`. A web unit moved before the domains its handlers read would need those handlers declared in a header while they stayed in `src.ino` — the reach-back pattern the owner's no-`globals.h` ruling forbids — or would own one variable and no code. So the children went in the order the graph allows: storage and settings, sensors, the data domains that consume them, display and navigation state, and the web server last, when everything it reads is published. #264's acceptance is met at the end regardless of order; it was measured and posted on #264.

Recorded in: #270's body, inventory §10.

### 3.2 `initSerialLog()` became `initSerialLog(bool rtcOk)`

It read `rtcAvailable`, which the RTC domain owns. Publishing that variable through `logging.h` would have been an extern reaching back into `src.ino`. Its single caller, `setup()`, passes the value: the same read of the same variable at the same moment. The proof attributes the +8 bytes in `setup`. Recorded in: #269, inventory §9.

### 3.3 Where a few things landed

- `src/fc_config.h` (started in band 2) holds the pin map: `SD_CS`, `SPI_*`, `FRAM_CS`, `TFT_BL`, `CTP_INT`, `BUTTON_A/B/C`.
- `src/fc_version.h` holds `FW_VERSION` (band 3e): `src.ino` and `web.cpp` both show it and one file is where a bump goes. CLAUDE.md's Versioning pointer was updated in the same PR.
- The timeout preset tables and `findTimeoutIndex` are `settings`, not display: they define what the sleep settings may be.
- `framFlushToSD` lives in `weather` (as #272's text proposed): it flushes the battery ring and the weather ring, both reachable through headers after band 3b, and `weather` is the higher of the two domains.
- `ui_state` (band 3d) holds state and no functions: `navigateScreen` indexes the LVGL screen objects the screen builders own, so the functions could not leave until band 4 — where they did, into `navigation`.
- A `touch` unit that no task listed: `handleWebDiags` reads `touchAvailable`, and #274 would have reached back for it.
- The RGB565 `COLOR_*` palette and the LVGL draw-buffer defines are `display.h`'s.
- The WiFi/NTP flags and the credential placeholders are private to `web.cpp`; nothing outside reads them, and a header is no place for credentials even as placeholders. **This is where #99 replaces them.**
- Band 4's `initLVGL` stays in `src.ino`: it builds every screen and wires the port, the composition root. `lvglTickCb` lost `static` because `initLVGL` registers it.
- Band 4 is one branch and one PR rather than five merged children: see §4.

### 3.4 Two corrections to the #215 diagnosis

- **The relocation graph never counted read-only data.** `reference-graph.py` took `nm` classes B/b/D/d as variables and skipped R/r, so every `const` table — `tzPresets`, the timeout tables, the 1,943-byte BSEC config blob — was invisible to the fan-in tables, the cut set and the reference sets the band-2 and 3a proofs compared. Found when `initBME688` would not compile without the blob (band 3b). Fixed; the cut set was unchanged (the corrected pool was 79 variables with the same 22-variable cut set on the post-3a object), so no ordering decision changed. The band-3b proof was re-run against a rebuilt baseline with the fixed graph. **Appendix A/B of the inventory still show the pre-correction numbers, as of `main` before E4-3; §11 says so.**
- **`gnrmcFixThisCycle` is write-only dead state** since #115: set in `parseNMEA` and cleared by `handleWebGpsReset`, read by nothing. The compiler had eliminated it as a static. It is published now (one byte and its stores). Deleting it is the owner's call — a behaviour question, not a move.

## 5. Process faults, recorded

- **Band 3e's baseline raced the extraction.** The in-worktree baseline build was started, and the extraction ran while PlatformIO was still compiling libraries; it picked up post-move source and failed on it, which is how it was noticed. The before-side artefacts for that proof came from a scratch worktree at `main` (7bfefa7). Band 4 captured every baseline before touching the tree. Rule: capture the baseline (nm, graph, ELF, map) **before** running `extract_unit.py`.
- **A harness fault that would have deleted a `switch` case.** The existing-prototype matcher accepted any prefix and matched `case SCREEN_COMPASS: updateCompassData(); …; break;` inside `updateDisplay`. The dry run showed it; nothing was written; it now requires type words at column 0 and nothing after the semicolon.
- Everything else the build found — a missing include, a define left behind, a static callback referenced before its definition, a preprocessor guard the harness does not carry — is listed per band in the inventory and fixed in the harness where it could be.

## 6. Where the evidence is, and how to check it

- Per band: inventory §9–§15 (what moved, calls for review, harness changes, measured figures).
- Raw verifier output per band: [`e4-proofs/`](e4-proofs/), one file per proof, exactly as `scripts/verify_extraction.py` printed it.
- The method: `scripts/reference-graph.py` (who uses what, from relocations), `scripts/extract_unit.py` (the move), `scripts/verify_extraction.py` (the proof). Each has a docstring that is the usage.
- To re-check a band: check out the merge commit's parent, `pio run -e feather_s3`, capture `nm --print-size --defined-only` over `.pio/build/feather_s3/src/*.o` and `python scripts/reference-graph.py --json --raw`, check out the merge commit, build again, and run `verify_extraction.py` with the `--moved`/`--published` lists from the commit message.
