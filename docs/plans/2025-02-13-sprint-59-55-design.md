## #59 — Serial Log to SD Card with Download

### Problem

Serial output goes to an in-memory 4KB ring buffer and a web serial monitor, but
is lost on reboot. There's no persistent log history and no way to retrieve logs
from a previous boot cycle.

### Solution

Write every `logPrint`/`logPrintf` call to both the ring buffer and an SD log file.
One file per boot cycle with smart retention.

### File Layout

```
/logs/
  serial_20260213_100500.log   ← boot at 10:05:00 on Feb 13
  serial_20260213_142300.log   ← boot at 14:23:00 on Feb 13
  serial_20260212_080000.log   ← boot at 08:00:00 on Feb 12
```

### Retention Logic ("Smart Rotation")

On boot, scan `/logs/` and check the timestamp of the most recent existing log:

- **Normal operation** (most recent log < 48h old): Delete files older than 48 hours.
- **Returning from extended off** (most recent log >= 48h old): Keep ALL existing logs.
  After 24 hours of uptime, switch to normal 48-hour rotation.

Constants (easy to change):
```c
#define LOG_RETENTION_HOURS     48    // Normal retention window
#define LOG_GRACE_HOURS         24    // Grace period after extended off
```

Periodic rotation check runs hourly in loop().

### Write Buffering

To avoid an SD write per log line:
- 512-byte RAM buffer accumulates log output
- Flush to SD on: buffer full, every 5 seconds, or explicit flush
- `serialRingAppend()` calls both ring buffer insert and SD buffer append

### Web Endpoints

- `/logs` — HTML page listing log files with sizes, timestamps, download links
- `/logs/download?file=<filename>` — Streams raw log file content for download
- Existing `/serial` and `/serial-data` unchanged (live ring buffer)

### Boot Sequence

1. `initSerialLog()` after `initSD()` and `initRTC()`
2. Create `/logs/` directory if missing
3. Build filename from RTC time: `serial_YYYYMMDD_HHMMSS.log`
4. Run smart rotation (scan dir, check ages, delete expired)
5. Open log file for append
6. All subsequent `logPrint` calls write to both ring buffer and SD

### Error Handling

- SD unavailable: Log to ring buffer only (existing behavior)
- SD write failure: Close and reopen file, retry once
- `/logs/` dir missing: Create it
- Log file open failure: Set flag, skip SD writes, log warning to serial

## #55 — ENV Screen Pressure Wrap Fix

### Problem

Pressure string `"1013.2 hPa (29.93\")"` is ~26 chars at textSize 2, starting at
x=110 on a 320px display. At ~12px/char, this extends to ~422px — wrapping past
the screen edge.

### Fix

Switch ENV screen values from `setTextSize(2)` to `setTextSize(1)`. This gives
~6px/char, fitting ~35 chars in the available 210px (x=110 to x=320). Adjust line
height from 28px to 14px. This also frees vertical space for additional data.
